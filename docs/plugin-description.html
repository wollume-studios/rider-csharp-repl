A C# REPL tool window for Rider, the replacement for Rider's C# Interactive window, which Rider 2026.3 removed. Run C# snippets in a persistent Roslyn scripting session, see your variables, reference your projects, and turn the session into a .NET 10 single-file app when it grows.

REPL

  • Auto-run (toggle, remembered): Enter runs the command and adds a missing ; when that completes it; Shift+Enter inserts a new line. In manual mode Enter collects lines until the command is complete and Shift+Enter runs now.
  • Nothing runs that you can't see: in manual mode a box shows the pending code that the next complete command will run with, so two commands are never merged silently.
  • Completion while typing (and on Ctrl+Space): the session's variables, methods and types, members after a ., namespaces, referenced projects' and packages' types, keywords. Enter or Tab inserts, and never runs the input while the popup shows.
  • History and input with C# highlighting in your color scheme: keywords and strings, and also method calls, extension methods, properties, locals, parameters and types, as Rider colors them in an editor. Console output, results and errors. Up/Down step through earlier commands, Escape clears the input.
  • Variables table like the debugger's (Name, Value, Type), with expandable fields and properties. The last exception is $exception; [inspect ›] in the history selects it.
  • The session runs in its own .NET process: a crash, an endless loop or Environment.Exit never takes Rider down. Stop kills a command that does not finish; Reset starts over and keeps the references.

References

  • Drag a project from Solution Explorer, or a .csproj / .dll from the file manager, onto the window; or Reference in C# REPL on a project node; or + Reference: a solution project, a DLL or a NuGet package: a picker lists the packages your solution references and searches nuget.org, with a version list. Projects are built first.
  • When a referenced project changes or is built, a banner offers Rebuild, Rebuild and replay the commands, or Rebuild and restore variables, or to ignore the change (once, for the session, forever).

Single-file apps

  • To Single-File App: the session, in a new scratch file, as a .NET 10 file-based app that compiles and runs like the session (references become #:project / #:package directives); a variant leaves out the commands that threw.
  • Dump Variables: a new single-file app (a scratch file) with the current variables as C# code.
  • Run Single-File App (editor menu, ▶ on the first line of a scratch or other file-based app Rider has no Run button for): dotnet run in the Run tool window.
  • New C# Single-File App (File › New), Add Project Reference Directive (editor menu), and dropping a project onto a single-file app's editor inserts #:project.

Note: exports and dumps are scratch files outside the solution. Rider 2026.3 may mark their symbols as errors although the file compiles and runs (Run Single-File App, dotnet run); Rider's support for file-based apps in scratch files is still unstable.

Settings

Settings › Tools › C# REPL: auto-run default, variables table right of the history or below the input, ignore project changes forever.

Status

Early version (0.x): expect rough edges. Please report problems on GitHub.

Requirements

Rider 2026.3 or later. A .NET 8 or later runtime runs the session; referencing projects and NuGet packages needs a .NET SDK, and running exported single-file apps the .NET 10 SDK. Referenced projects and DLLs target net8.0 or later, or netstandard2.x.
